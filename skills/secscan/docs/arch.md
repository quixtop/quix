# secscan — architecture

Spec: `docs/spec/secscan.md` (§ 4.6 holds the component tree and the engine table).

## Decisions
- secscan runs the engines and calls the rest: `scan.py` runs and merges the engines; `claude-security` does the verified code review and patch files, `security-audit` the domain checklists in depth — both on a default run, since `claude-security` has four dedicated categories and one breadth sweep while `security-audit` has a guide per domain — why: each outside tool is better at its part than a rebuilt copy, and the owner wants the best quality at every point (checked 25 Oct 26: every lens of the removed own review is covered by one of the two; the three left over — API footguns, ASVS ids, precedents — travel as instructions in each `security-audit` call, while for `claude-security`, whose workflow takes no free text, secscan applies the precedents and ASVS ids to its findings itself, and footguns are covered only when `security-audit` runs).
- Every called tool reads the masked mirror ("Scan codebase" takes it as its scan path; `security-audit` is pointed at it); only "Scan changes" and "Suggest patches", which take no path and read the live checkout, run behind a secrets gate (`keyscan -a --strict` over every file, ignored ones too, + all history, both `ran`, no secret-named file, history hits revoked) — why: the called tools mask nothing themselves.
- One Finding shape for every source, merged per root cause (same file, category, package and commit; a member's own line always joins; within 3 lines of the cluster's first line, another engine with a compatible CWE or the same engine with the same CWE; a secret only on the same line) — why: one root cause, one line.
- Engines run in parallel from one thread pool, each in its own process group; coverage keeps the mode's engine order — why: the run then takes as long as its slowest engine (116 s → 55 s on `~/.agents`), and a stop kills every group.
- Engine results verified by fresh isolated subagents (a panel of three for high/critical and groups), one lens: is the match real; inline and labelled when secscan runs nested — why: no outside tool verifies engine output, and an author grading its own finding confirms it.
- Engine data in a user cache refreshed by `scan.py update`, the semgrep packs merged there into one rules file — why: the Semgrep Rules License forbids bundling, scans stay offline, and each rule loads once.
- Engines run with explicit config, an allowlisted environment and an empty HOME (except gosec), from an empty folder (keyscan and actionlint from the repo top, gosec from each module root); every repo suppression marker is listed — why: a repo or a user setting must not silence a scan unseen, and engines never see credentials.
- A known-bad engine is identified without running it (install path, Go build info) — why: a compromised binary must not run even once.
- secscan's own reads (the engine verifiers) go through a masked mirror of the repo, re-scanned after masking — why: no secret value may reach the transcript.
- keyscan stays a separate script in `~/.agents/bin`, linked from `~/.local/bin` — why: the commit gate must stay fast and dependency-light.
- Fixes hand off to `/rev` through an audit entry in `docs/logs/revlogs.md`, marked as a fix hand-off, not an audit baseline — why: one owner for the failing-test-first gate, through its existing input.

## Data flow
`SKILL.md` → `scan.py <mode>` (engines in parallel → findings, groups, coverage, suppressions; a stderr line per engine) → `scan.py mirror` (masked copy of the whole repo, re-scanned) → engine-result verifiers on the mirror → `claude-security` "Scan codebase" (its report moved out of the mirror at once) and `security-audit` on the mirror, one after the other (one of them alone for `quick`, `agents`, `audit`); "Scan changes" on the repo only behind the secrets gate → report (engine results + each called tool's job, report path and counts; `scan.py report` on `--report`) → fixes on request (`claude-security` patch files; engine findings via `/rev`) → close-check → clean-up of the mirrors.

# spec

Every project doc in one skill — spec, plan, requirements, architecture, design and tasks before the build, or from the code after it; reviewed, filed on one go.

## Install

```bash
curl -fsSL https://quixtop.com/i | sh -s -- spec
```

## Usage

Invoke it as `/spec` in Claude Code.

Every project doc in one skill. Before the build: turn a feature — given, or taken from the conversation — into a reviewed spec, plan, reqs, arch (with its diagrams), design and tasks, filed on ONE go, then offer /dev; in full mode it first drills the idea and attacks it with a panel of agents, and a panel reviews the spec. After the build: the same set plus README and API docs, written from the code. Keeps docs in sync: /spec update | verify | changelog; /spec review <file> reviews any doc. Use to spec a feature, think an idea through (/spec think), document existing code, update docs after changes, check docs against the code, review a doc, or write release notes — not quick ideation (superpowers:brainstorming) or the build itself (/dev).
